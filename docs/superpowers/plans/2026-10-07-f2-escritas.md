## Contratos (todas as tarefas usam)

**Item (board):**
```
{ id, nome, cor, un, necessaria, separada, falta, faltaG, status,
  baixada, resta, restaG, obsAlmox, obsPcp, previsao, resolvidoEm, versao, editavel }
```
- `baixada`: número, 0 quando vazio.
- `resta`: `falta === null ? null : max(0, falta − baixada)`.
- `restaG`: `faltaG` proporcional a `resta`; `null` quando não houver `faltaG`.
- `versao`: `atualizado_em_app` ou `''`.
- `editavel`: `true` para linhas da FALTANTES; `false` para itens lidos do texto da CAIXAS GANHAS.

**Caixa (board):** os campos da F1 mais:
- `previsao` e `observacao` (da CAIXAS_PCP);
- `colunaManual` (ColunaId ou `null`, já com a regra de expiração);
- `versao` (`atualizado_em` da CAIXAS_PCP ou `''`);
- `historico`: `[{ quando, usuario, texto, ploomes: 'PENDENTE'|'ENVIADO'|'ERRO' }]`, até 30, do mais novo para o mais antigo.

**Board:** `{ geradoEm, caixas, avisos, usuarios: string[] }`.

**Ação (POST /pcp-acao):**
- Corpo: `{ tipo, dealId, itemId?, valor, versao, justificativa? }`.
- Respostas:
  - `200 { ok: true, versao, historico }`;
  - `400 { erro }`;
  - `401 { erro }`;
  - `409 { erro: 'Alguém alterou esta caixa agora há pouco.' }`.

### Task 2: Regras das ações no n8n (`n8n/src/acoes.js`)

Funções puras. Um arquivo novo, que entra em `ARQUIVOS` do `carregar.js` **antes** de `api.js`.

- `validarAcao(corpo, perfil) → { ok: true, acao } | { ok: false, status: 400, erro }`
  - `tipo` precisa ser um dos 7 tipos; `dealId` é obrigatório.
  - Os tipos de item exigem `itemId`.
  - `baixa`: `valor` é um número maior que 0.
  - `previsao_*`: `valor` é `''` ou `aaaa-mm-dd`.
  - `obs_*`: texto com no máximo 500 caracteres.
  - `responsavel`: texto.
  - `mover`: `valor` é uma das 6 ColunaId. Para perfil diferente de ADM, a justificativa, sem os espaços das pontas, precisa ter pelo menos 15 caracteres; senão responde `400 'Justificativa precisa de pelo menos 15 caracteres.'`.
- `aplicarAcao(acao, alvo, contexto) → { ok, status?, erro?, gravacao, historico }`
  - `alvo` é a linha atual: FALTANTES ou CAIXAS_PCP, ou `null` se a caixa ainda não tiver linha.
  - `contexto = { usuario, email, agora (ISO), os, nomeItem, un }`.
  - Confere a versão. A diferente devolve `409`.
  - Baixa acima do que resta devolve `400 'Falta só <resta> <un>'`.
  - `gravacao` traz `{ aba, chave: { coluna, valor }, campos }`.
  - `historico` traz uma linha completa do HISTORICO_APP, com `id` vindo de um gerador injetado em `contexto.gerarId`, `ploomes_status: 'PENDENTE'`, `tentativas: 0` e o `texto` conforme a spec.
- `textoDaAcao(acao, ctx)` gera os textos da tabela da spec. Datas no texto saem como `dd/mm`.

Os testes ficam em `n8n/test/acoes.test.js` e cobrem:
- cada tipo válido e inválido;
- a justificativa para ADM e para não-ADM;
- o 409 por versão;
- baixa no limite exato e acima do limite;
- a soma de `qtd_baixada`;
- cada texto da tabela;
- a caixa sem linha prévia, com versão `''`, que cria a linha.

Siga TDD e faça um commit.

### Task 3: Board com os dados novos (`montarCaixas.js` + `api.js`)

- A assinatura passa a ser `montarCaixas(faltantes, ganhas, hoje, extras)`, com `extras = { caixasPcp, historico }`. As abas novas são opcionais, e as chamadas antigas continuam funcionando.
- O item ganha os campos do contrato.
- `itemEstaAberto` passa a usar `resta` (`null` conta como aberto).
- Caixa:
  - recebe `previsao`, `observacao` e `versao` da CAIXAS_PCP;
  - `colunaManual` vale até qualquer item da caixa ter `atualizado_em_app` ou `data_atualizacao` (normalizada) posterior a `coluna_manual_em`;
  - `historico` agrupa as linhas por `deal_id`, ordena pela mais nova e corta em 30.
- `montarRespostaBoard(estado, faltantes, ganhas, agora, extras)` inclui `usuarios`, os nomes dos usuários com `ativo` verdadeiro, ordenados.
- `api.js` ganha `processarAcao(estado, cabecalho, corpo, linhas, agora, gerarId)`. Ela:
  - valida a sessão;
  - chama `validarAcao` e `aplicarAcao`;
  - limpa `estado.board` em caso de sucesso;
  - devolve `{ status, body, gravacao, historico }`.

A atualização da planilha fica nos nodes do workflow, não no Code node.

Os testes estendem `montarCaixas.test.js` e `auth-api.test.js` (ou criam `board-f2.test.js`). Cobrir `resta`/`restaG`, `editavel`, a expiração da coluna manual, o corte do histórico em 30, `usuarios` e o fluxo de `processarAcao` (401, 400, 409, 200 limpando o cache). Siga TDD e faça um commit.

### Task 4: Envio ao Ploomes (`n8n/src/envioPloomes.js`)

- `selecionarPendentes(linhas, max=20)`: linhas com `PENDENTE` e `tentativas < 5`, da mais antiga para a mais nova.
- `montarRegistro(linha, contactId)`: monta `{ DealId: Number(deal_id), ContactId (se houver), Content: '[PCP · OS ' + os + '] ' + texto, Date: quando }`.
- `resultadoEnvio(linha, resposta)`, onde resposta é `{ status, body }`, devolve os campos a gravar:
  - 2xx: `ENVIADO` e `ploomes_id`;
  - 429: `{ parar: true }`, sem alterar a linha;
  - outro erro: `tentativas + 1`, mais `ERRO` e a mensagem quando chegar a 5.

Testes em `n8n/test/envio-ploomes.test.js`. Siga TDD e faça um commit.

### Task 7: Front — painel editável, avisos, histórico e card

- Componente `Aviso` (toast de uma linha no rodapé, `role="status"`, some em 3,4 s).
- Hook `useAcao(token, recarregar)`. Ele:
  - envia a ação;
  - no sucesso, mostra o aviso e recarrega o board;
  - no `409`, mostra o aviso de conflito e recarrega;
  - no `401`, chama `aoExpirar`;
  - em outro erro, mostra "Não foi possível salvar. Tente de novo."
- O `useBoard` passa a expor `recarregar` para o App.
- Painel:
  - topo com Responsável (`<select>` com `board.usuarios` e a opção vazia "Sem responsável"), Previsão geral (`<input type="date">`) e Observação geral (`<textarea>`, salva no blur se mudou);
  - itens editáveis com a conta nova, o campo "Chegou" (`inputMode="decimal"`) com o botão "Registrar baixa" e o erro da validação sob o campo, a Previsão do item e a Observação do item (`obsPcp`);
  - `obsAlmox` aparece como texto do almoxarifado;
  - itens não editáveis mostram "Item lido da planilha de caixas ganhas; não pode ser alterado aqui.";
  - "Mover para": 6 botões, com a coluna atual desabilitada. Para quem não é ADM, abre a justificativa com o contador `n/15` e o botão "Confirmar e mover";
  - histórico com os selos `enviado ao Ploomes` / `aguardando Ploomes` / `falhou no Ploomes`;
  - sai a nota "passam a ser editáveis na próxima fase".
- Card: rodapé com `previsão dd/mm` quando a caixa tem previsão.
- O perfil vem da `Sessao.perfil`.
- Estilos no `app.css`, na mesma direção visual (campos de 38px, raio 4–5px, ouro só no botão principal "Registrar baixa").
